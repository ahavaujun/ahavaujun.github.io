## What this is

Personal academic/portfolio site for JunYoung Lee, deployed at `https://ahavaujun.github.io/`.
Nominally a Hugo site (theme `hugo-theme-introduction`, vendored under `themes/`), but in practice
the homepage is a single hand-written static HTML page — see Architecture below before editing anything.

## The one thing you must know: editing the homepage

The visible site is a **single self-contained HTML file** (inline `<style>` + inline `<script>`,
no Go template directives). It does **not** read from the `content/en/home/*.md` markdown files —
those are leftover theme content and are NOT rendered into the live page. Editing markdown will not
change the site.

The page is an **editorial / academic** design (light + dark toggle): Fraunces (display) + Newsreader
(body serif) + IBM Plex Mono (metadata), warm paper background with an oxblood accent. The **content
source of truth is the CV** at `docs/CV_이준영.pdf` (a served copy lives at `static/JunYoung_Lee_CV.pdf`,
linked from the page as `/JunYoung_Lee_CV.pdf`). When the CV changes, update the HTML to match.

That HTML file exists as **three byte-identical copies that must be kept in sync**:

- `layouts/index.html` — Hugo layout, overrides the theme's homepage
- `static/index.html`  — Hugo static passthrough
- `index.html` (repo root) — committed build artifact

When changing the homepage (about text, projects, news, awards, theme CSS, etc.), edit
`layouts/index.html` and mirror the exact same change into `static/index.html` and root `index.html`.
The commit history ("fix: remove empty layouts/index.html so static/index.html is served",
"fix index error") is the result of these copies drifting out of sync — do not let them diverge.

## Build & deploy

- **No local Hugo install** is assumed (not present in this environment). Because the homepage is
  static HTML, the fastest preview is to open `layouts/index.html` directly in a browser.
- If Hugo is available, `hugo server` previews and `hugo --minify` builds into `public/`.
- **Deployment is automatic**: `.github/workflows/hugo.yml` runs on push to `main`, builds with
  `hugo --minify`, and publishes `./public` to the `gh-pages` branch (the served branch).
- The committed `public/` directory and the root-level build artifacts (`index.xml`, `sitemap.xml`,
  `404.html`, `css/`, `js/`, `categories/`, `tags/`) are generated output regenerated by CI — they
  are not the source of truth and should not be hand-edited. Canonical sources are `layouts/`,
  `static/`, `content/`, `hugo.toml`, and `themes/`.

`github = konhoe`, `email = knj7973@yonsei.ac.kr`), while the deployed site and the hand-coded HTML use
the **`ahavaujun` identity** (`og:url = https://ahavaujun.github.io/`, `github.com/ahavaujun`). If you
touch deploy URLs, social links, or canonical metadata, reconcile these two rather than trusting either
blindly.

## Assets

Homepage images/GIFs are referenced by absolute path (e.g. `/home/junyoung.jpg`, `/img/squat-demo.gif`)
and live in `static/` (`static/img/`) and `home/`. Keep these paths absolute to match the GitHub Pages
root deployment (`canonifyURLs`/`relativeURLs` are off in `hugo.toml`).
